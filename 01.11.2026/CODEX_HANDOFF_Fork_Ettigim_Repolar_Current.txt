## Uygulama
1. Kullanıcının seçtiği ana çalışma dizinini tespit et; belirsizse sor. Mevcut dosyalara dokunma.
2. GitHub liste URL'sini tekrar kontrol et; liste değiştiyse farkları raporla, sessizce kapsam değiştirme.
3. Dizinleri oluştur. Her hedef dizin mevcutsa içeriği incele; üzerine yazma veya yeniden klonlama yapma. Gerekirse kullanıcı onayı iste.
4. Her repoyu belirtilen hedefe `git clone https://github.com/kemaldemirag/<repo>.git '<hedef>'` ile klonla. `origin` kullanıcının forkunu göstermeli.
5. GitHub API veya repo metadata ile her forkun gerçek `parent`/`source` bilgisini doğrula. Doğrulanmış parent varsa `git remote add upstream <parent-clone-url>`; doğrulanamazsa upstream ekleme ve raporla. Fork statüsünü yalnız liste başlığından varsayma.
6. Her repo için `git remote -v`, `git status --short`, `git rev-parse HEAD`, varsayılan branch, ana diller, LICENSE, README, temel yapı ve bağımlılıkları salt okunur incele.
7. `001-Kayıt Notları/` içine REPO_INDEX.md, `002-Proje Dokümantasyonu/` içine WORKSPACE_OVERVIEW.md; `003-Referans Kaynaklar/003-Repolar/` içine SOURCE_LINKS.md yaz.
8. `003-Proje Kayıtları/002-Teknik Çıktı Kayıtları/` içine CLONE_REPORT.md ve VERIFICATION_REPORT.md yaz. Başarısız klonları, upstream belirsizliklerini, duplicate'leri açıkça kaydet.
9. README.md ve PROJECT-MANIFEST.json oluştur. Manifest her repo için başlık, yerel yol, origin, doğrulanmış upstream (veya null), commit SHA, branch, klonlama sonucu, zaman bilgisi içermeli.
10. Son raporda tam yolları, başarılı/başarısız repo sayılarını, çalışma ağacı durumunu ve sonraki geliştirme önerilerini belirt.

## Yasaklar
- `git push`, `gh repo create`, `gh pr create`, PR açma, force-push, branch silme, mevcut .git dizinini silme.
- Kaynak kodu veya konfigürasyonları değiştirme, bağımlılık kurma, testleri çalıştırma (ayrı onay olmadan).
- Yerel kopyaları bağımsız yeni GitHub repoları olarak yayınlama.
- Forkun parent URL'sini tahmin etme.

## Tamamlanma kriterleri
Dört depo ya başarıyla doğru klasöre klonlanmış ya da nedeni belgelenmiş; origin/upstream politikası doğrulanmış; envanter, manifest ve loglar oluşturulmuş; hiçbir uzak yazma işlemi yapılmamış olmalı.
