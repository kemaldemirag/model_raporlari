## Codex yürütme talimatları
1. İşlem öncesinde mevcut çalışma dizinini, disk alanını, git sürümünü ve hedef klasörün varlığını kontrol et. Mevcut veriyi silme, üzerine yazma veya taşıma.
2. GitHub listesini mümkünse yeniden oku; listede farklı repo sayısı veya erişim sorunu varsa raporla, sessizce kapsam değiştirme.
3. Yukarıdaki klasör ağacını oluştur. Kullanıcıdan hedef ana dizin verilmemişse çalıştığın izinli çalışma dizini altında oluştur; masaüstü veya Drive'a otomatik yönlendirme yapma.
4. Her kaynak repo için `git ls-remote <url> HEAD` ile erişimi kontrol et. Başarısızsa kayda geçir ve diğer repolara devam et.
5. Repo hedef klasörü boş/yok ise `git clone <url> <hedef>` çalıştır. Mevcut repo varsa remote URL ve çalışma ağacı durumunu incele; otomatik reset, pull, clean veya overwrite yapma.
6. Her repo için varsayılan branch, HEAD commit, origin URL, lisans dosyası, README, temel diller, test/build yönergeleri ve varsa submodule/LFS bilgilerini kaydet. Submodule/LFS indirmelerini otomatik başlatma; ihtiyaç varsa öner.
7. `001-Kayıt Notları ve Dokümantasyon/003-Referans Kaynaklar/003-Repolar/REPO_INDEX.md` içine kaynak URL, yerel konum, sınıflandırma, commit SHA ve erişim durumunu yaz.
8. `001-Kayıt Notları ve Dokümantasyon/002-Proje Dokümantasyonu/CODEX_HANDOFF.md` dosyasına bu talimatların kopyasını koy. `README.md` ve `PROJECT-MANIFEST.json` oluştur.
9. `003-Proje Kayıtları/002-Teknik Çıktı Kayıtları/CLONE_REPORT.md` içinde yapılan/atlanan işlemleri, hata mesajlarını, doğrulama sonuçlarını ve sonraki önerileri raporla.
10. Repo içindeki kaynak kodları bu kurulum aşamasında değiştirme; commit, push, PR, fork, GitHub repo creation, git remote set-url, git clean ve git reset --hard YASAK. Upstream katkı yalnızca kullanıcıdan ayrı açık onayla yapılabilir.
11. Kapanışta 3/3 doğrulama tablosu sun: kaynak repo, hedef, klonlama durumu, HEAD SHA, çalışma ağacı temizliği. Başarısız adımları başarı gibi gösterme.
